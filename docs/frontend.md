# 前端说明

前端在 `web/`，按设计原型（<https://claude.ai/artifact/QgNXZkh5JKpCac8gfZcYmE>）实现，共五个页面：总览、服务器、任务、结果与评测、对比。

技术栈：Vite + React 18 + TypeScript，路由用 HashRouter，不依赖外部字体和 CDN，可在内网使用。

## 开发与构建

```sh
cd web
npm ci
npm run dev      # http://localhost:5173/ui/ ，/api 代理到 127.0.0.1:8000
npm run build    # 产物在 web/dist
npm test         # 单元测试（node --test，需要默认开启类型擦除的 Node 22.18 及以上）
```

中心服务启动时，如果 `GNM_WEB_DIR`（默认 `web/dist`）下有 `index.html`，就在 `/ui/` 托管前端，并把 `/` 重定向到 `/ui/`。没有构建产物时只提供接口，不影响现有行为。

## 目录

```
web/src/api/       接口封装与类型（types.ts 与后端 schemas.py 字段一致）
web/src/mock/      后端尚未提供的接口的模拟数据
web/src/lib/       格式化、卡状态判定、轮询 hook
web/src/components 通用组件
web/src/pages/     五个页面（对比页的图片对比视图在 CompareImages.tsx 和 pages/compare/）
web/e2e/           对比页的 Playwright 脚本（不在项目里安装依赖，见“对比页”）
```

### 模拟数据兜底

`api/client.ts` 的 `withFallback` 在接口返回 FastAPI 默认的 404（`{"detail": "Not Found"}`，即路由未注册）时，把该功能切换到 `web/src/mock` 下的模拟数据，页面上显示“示例数据 · xx接口未上线”标记。分三组独立判断：

- `jobs`：任务接口。
- `scheduler`：调度模式接口。
- `results`：结果、评测、对比接口。

业务上的 404（例如“服务器不存在”）的 detail 不是 `Not Found`，不会触发兜底。

### 卡状态判定

`lib/format.ts` 的 `deviceState()` 把每张卡归为：空闲、平台任务占用（`devices[].job_id` 非空）、外部占用、异常（health 不是 OK）、离线（服务器不在线）。`job_id` 字段来自第 2 步；更早版本的接口没有这个字段时，非空闲卡统一显示为“占用”。

## 对接说明

### 调度模式与排队原因

- 任务页的“严格按序”开关对接 `GET/PATCH /api/scheduler`，侧栏显示当前模式。切换只保存在中心服务内存中，重启后回到 `GNM_SCHEDULE_STRICT` 的值。
- 任务详情和总览的排队列表显示 `JobOut.wait_reason`（为空时只显示队列位置）。
- 后端没有 `/api/scheduler` 时，前端隐藏开关，显示“调度模式由服务端配置”。

### 结果与评测的对接方式

第 3 步的接口已经覆盖结果浏览、评测和多组对比，前端按它实现，没有新增后端需求。几处取舍：

- 结果集没有类型字段。样本浏览和对比页按样本字段决定展示方式：有 `text` 按文字展示（识别结果、参考答案、错字高亮），否则有 `image` 按图片网格展示，其他字段作为附加列原样显示。发起评测时读第一条样本，默认勾选对应类型的指标。
- 列表的指标列只显示至少一个结果集有值的指标，显示名、单位、方向都来自 `GET /api/evaluators`。
- 对比页可以任选基线。接口的样本顺序和 `asc`/`desc` 排序以第一个结果集为准，所以请求时把基线放在 `ids` 的第一位；“基线最差优先”按指标方向换成 `asc` 或 `desc`。
- 参考图用样本里的 `ref_image`（可以是服务器上的绝对路径），通过同一个 `/file` 接口读取。
- 样本浏览不再提供按 id 搜索，接口没有这个参数。数据量大时如果需要，可以给 `/samples` 加一个 `q`。

用第 3 步的中心服务和 Agent 实测过：登记 2 组图像、2 组 OCR 结果，发起 PSNR、SSIM、LPIPS、OCR-A、CER、1-NED 评测，列表、样本浏览、评测记录（含 LPIPS 未安装时的单项错误）、图像和文字对比都显示正常。

### 对比页

设计稿：<https://claude.ai/artifact/QZqFpCQxLGL8R5HFNCYxY3>。代码在 `pages/Compare.tsx`（布局、推理结果选择、指标视图）、`pages/CompareImages.tsx`（图片对比视图的编排）和 `pages/compare/`（图片列表、请求调度、缩略图栏、画布渲染等，见下文）。

进入对比页时左侧导航自动折叠成图标栏，鼠标悬停或键盘聚焦时浮层展开，不挤压内容；其他页面不变。手机宽度下导航照常横排。

页面从左到右分三栏，右上角可在“指标”和“图片对比”两个视图间切换（默认图片对比）：

1. **推理结果**：列出全部结果集，勾选的排在前面，可按名称筛选。勾选结果写入地址栏的 `ids`，两个视图共用。
2. **缩略图**（仅图片对比视图）：每个勾选的结果集一列，列出它的全部图片，按文件名字母序排列，当前显示的那张用该结果的颜色描边。
3. **主区域**：指标视图是原来的指标表、点图和逐样本对比；图片对比视图每个结果集只显示一张图，多个结果组成网格（1 组 1 列，2–4 组 2 列，更多 3 列）。

推理结果栏和缩略图栏都可以手动折叠成竖条，折叠和展开带宽度过渡和淡入淡出动画。

目标是同时对比多组、每组 5000–20000 张、单张 4K–8K 的 PNG/TIFF 时，换图、滚动缩略图、增加结果集、按住对比和缩放平移都不卡顿。做法概括为：列表一次取全、图片按需取派生图（接口见 [api.md](api.md) 的“对比页的图片接口”）、缩略图栏虚拟滚动、格子用 canvas 绘制且缩放不经过 React、请求统一调度、解码结果按内存预算缓存。

#### 图片列表

图片对比视图对每个勾选的结果集请求一次 `GET /results/{id}/images`，得到全部图片的 `[路径, 字节数, 版本号]`（gzip 后 2 万张约 50 KB）。列表已由后端按文件名（不含目录）字母序排序、同名按完整路径排序并去重，前端不再排序。

`compare/imageIndex.ts` 一次遍历建好索引（2 万张约 5 ms），模块级缓存最近 12 个结果集（正在显示的不淘汰），取消再勾选、在两个视图间切换都不重新读取。每次进入页面带 `If-None-Match` 在后台重新验证一次，列表变了按路径换算当前位置。图片宽高不在列表里，任一图片响应的 `X-Image-Width/Height` 到达时补上。字节数为 -1（文件不存在）的图不发请求，直接显示“文件不存在”。

逐样本对比（`/compare/samples`）只在指标视图请求，图片视图不再请求。

#### 切换与匹配

修饰键在 Mac 上是 ⌘（Ctrl+左键在 Mac 上会被系统当作右键），其他系统是 Ctrl，下表记作 Mod。

| 操作 | 效果 |
| --- | --- |
| 单击缩略图 | 只切换这一列对应的结果集，其他结果不变 |
| Mod + 单击缩略图 | 所有结果集切到同一序号；某个结果集图片较少时停在它的最后一张 |
| Alt + 单击缩略图 | 被点的结果集切到这张图，其他结果集各自选文件名编辑距离最小的图片（相同距离取排序靠前的） |
| 上一张 / 下一张按钮，← ↑ / → ↓ | 所有结果集各自前进或后退一张，保持当前对齐关系；焦点在输入框或按着修饰键时方向键不处理 |
| 按住图片右下角的按钮 | 同时对比 n 组时每张图上有 n−1 个按钮，按住时这张图换成对应结果集当前的图片，松开、移出或失焦后恢复；键盘按住空格或回车同样生效 |
| Mod + 滚轮 | 以鼠标位置为中心缩放，所有图片同步，范围 100%–1600%；Mac 触控板双指捏合同样生效 |
| Mod + 左键拖动 | 所有图片同步平移，平移范围限制在图片仍铺满显示区域之内 |
| − / + / 适应窗口 | 以中心缩放，或恢复 100% |

点结果名（网格表头或缩略图列头）可把它设为对齐基准，最近一次点击缩略图的结果也会成为基准。其他结果当前图片文件名中最长的一段数字与基准不同时，表头显示“编号不一致”，用于发现 Mod+单击 按序号同步时因缺图造成的错位。

Alt+单击分两步：文件名完全相同的结果集用索引里的“文件名 → 第一个序号”当帧切换；其余的交给 Web Worker（`compare/matchWorker.ts`）按编辑距离计算，结果与逐个计算完全相同。Worker 先用同序号、文件名中最长一段数字相同、去掉公共前后缀后相同的几张图求出较紧的上界，再全量扫描，超过上界的提前放弃。列表加载后就把文件名交给 Worker（最多 12 个结果集）；计算期间状态栏显示“Alt 文件名匹配中…”，期间又有新操作时丢弃结果。Worker 不可用时在主线程计算。

#### 画面与角标

每个格子是一个 canvas，由 `compare/CellRenderer.ts` 直接绘制，不经过 React。图片按原图宽高 contain 到 4:3 的显示区域，缩略图、预览、原图和瓦片都画进同一个矩形，切换层级时位置不跳：

1. **缩略图**（长边 256）：换图后先放大显示作占位。缩略图栏里已有的直接用，不再请求。
2. **预览**：档位取不小于格子长边设备像素的 1024 / 2048 / 3072。原图不超过档位时预览本身就是无损的。
3. **无损层**：放大后，或预览比屏幕像素还粗时叠加。原图是浏览器能直接显示的格式、不超过 12 MB 和 1677 万像素、且缩小不超过 2 倍时取整张原图；否则取当前缩放对应层级的可见瓦片（512²，第 l 层为原图缩小 2^l 倍；层级保证缩小不超过 2 倍，缩得更小会有摩尔纹），外加一圈预取。先画粗层再画细层，细层还没到的地方由粗层或预览垫底；瓦片按设备像素对齐，相邻瓦片之间没有缝。换到更细的层在手势中防抖 60 ms，换到更粗的层立即切换。

只有画的是原图像素（原图、第 0 层瓦片、无损预览）且一个原图像素不小于一个设备像素时才关闭插值，像素边缘清晰，便于看像素级差异；其余照常插值。

换图后新图还没有任何内容可画时，旧画面连同文件名最多保留 100 ms，之后显示放大的缩略图和“加载中”；连缩略图也没有时显示文件名。

右上角的角标描述画布上实际画出的内容：

| 角标 | 含义 |
| --- | --- |
| 缩略图 / 预览 | 画的是缩略图或有损预览 |
| 加载中 | 预览还没到，先显示放大的缩略图 |
| 无损 1/2ⁿ | 无损瓦片，原图缩小 2ⁿ 倍的那一层 |
| 原始像素 | 原图像素（整张原图、第 0 层瓦片或无损预览） |
| 原图 37% | 正在下载整张原图；节点和中心服务都生成不了预览时前面加“无法生成预览” |
| 仅显示预览 | 需要无损层，但瓦片生成不了，原图又太大（解码后超过内存预算的一半） |
| 文件不存在 / 图片过大 / 无法解码 / 无法生成预览 / 服务繁忙 | 请求失败（404 / 413 / 415 / 501 / 503 重试后），其他错误显示服务端的说明 |
| 已归一化 | 单独的角标：32 位或浮点数据按本图最大值缩放过 |

画布的 `data-tier`（`thumb` / `preview` / `lossless`）、`data-level`、`aria-label` 和格子下方的文件名也由渲染器写入，始终对应实际画出的图。

按住对比时直接用对方格子已解码的位图重画，两格尺寸相同，瓦片也通用，不发请求，当帧生效。

缩放和平移的状态在 `compare/viewStore.ts`，滚轮和拖动的原生监听直接改它，缩放比例文字和各格子在同一个 rAF 里更新，缩放、拖动期间没有 React 提交。浏览器默认把 Ctrl+滚轮当作页面缩放，React 的 `onWheel` 是 passive 监听无法阻止，所以挂的是 `passive: false` 的原生 `wheel` 监听。格子尺寸变化（折叠动画）时画布只被拉伸，停下 120 ms 或动画结束后才按设备像素重新分配；滚出视口的格子不画。

#### 缩略图栏

所有结果集共用一个虚拟滚动容器（`compare/ThumbPanel.tsx`）：行数取最长的列表，行高固定 112 px，只渲染可见行和上下各 4 行，列标题吸顶；总高度超过 1500 万像素时（Firefox 的元素高度上限约 1790 万像素）按比例映射滚动位置。

- 快速滚动（超过 2 px/ms）时行里只有序号和文件名，停下 80 ms 后才请求缩略图，可见行优先于上下多渲染的行；滚出范围的行释放请求，排队的丢弃，进行中的中止。已缓存的缩略图滚动中照常显示。缩略图栏折叠时不请求。
- 缩略图转成 objectURL 缓存，最多 3000 张，正在显示的不撤销。
- 鼠标在缩略图上停留 80 ms 后预取它的预览，按着 Mod 时预取所有结果集的同一序号，最多保留 4 个。
- 对齐基准结果集的当前图不在视口内时直接跳过去，不做平滑滚动。
- 列标题显示“当前 / 总数”；有缺失文件时悬停显示个数；列表超过 20 万张被截断时显示“只列出前 n 张”。

#### 请求调度

图片请求都经过 `compare/loader.ts`：

- 同一 URL 只请求一次，按引用计数共享；引用全部释放时排队的直接丢弃、进行中的中止，节点上还没开始解码的请求随之放弃。
- 同源 HTTP/1.1 只有 6 个连接，图片最多同时 5 个请求：缩略图栏最多 3 个，预取最多 2 个，总留一个给 `/api` 的 JSON 请求。页面走 HTTP/2 或 HTTP/3 时放宽到 16 个（缩略图 8 个、预取 6 个），部署方式见 README 的“部署建议”。
- 按优先级发出，数字小的先发：

| 优先级 | 请求 |
| --- | --- |
| 0 | 可见格子当前图的缩略图占位和预览 |
| 1 | 可见格子的无损层（视口内瓦片、原图） |
| 2 | 前进方向下一张的预览和缩略图、悬停预取 |
| 3 | 缩略图栏可见行 |
| 4 | 上一张、再下一张的预览，放大时下一张的无损层，瓦片外圈 |
| 5 | 缩略图栏上下多渲染的行 |

- 同一优先级内各格子的请求交错排队：多个结果集同时冷启动时，节点能同时解码不同的图，而不是先排完前两个格子的瓦片。
- 0、1 级还没取完时不发 3 级及以后的请求，免得它们占住节点的解码槽位。
- 连按方向键（两次间隔小于 120 ms）时，预览和无损层推迟到最后一次之后 100 ms 再请求，期间显示缩略图；被跳过的序号释放后直接丢弃。
- 503 和网络错误按 1、2、4、8 秒退避重试，服务端给的 `Retry-After` 更长时按它，最长 30 秒，最多 5 次；404、413、415 记住 30 秒，期间不再请求。
- 用 `createImageBitmap` 解码，同时最多 2 张 400 万像素以上的大图、4 张小图、8 张缩略图；它不支持的格式退回 `<img>` 解码。

#### 预取

`compare/prefetch.ts` 按最近一次上一张 / 下一张的方向（默认向后）预取各结果集下一张的预览和缩略图（2 级）；内存允许时再预取上一张和再下一张的预览（4 级），张数满足“结果集数 × (1 + 预取张数) × 预览字节数 ≤ 内存预算的一半”。放大时，等各格子的当前图都加载完，再预取下一张同一视口的无损层（4 级），总量不超过预算。换图后、缩放平移停下 150 ms 后重新计算，已有的同一请求只调整优先级，不再需要的释放。

#### 内存

- 解码后的位图放在 `compare/bitmapCache.ts` 的 LRU 里，预算为设备内存（GB）× 128 MB，限制在 384–1024 MB（浏览器不提供设备内存时按 4 GB 算），超出时淘汰最久没用的并 `close()`。正在任何格子里画的位图（包括按住对比时显示的）pin 住，不会被淘汰。
- 每帧第一次上传 GPU 的位图不超过 24 MB，其余推迟到下一帧，期间先画已有的更粗一层。
- 取消全部结果集时释放全部位图；离开对比页时中止全部请求、释放位图，缩略图只留 500 张，图片列表保留。

#### 示例数据模式

后端没有结果接口时（见“模拟数据兜底”），图片列表由示例样本编号生成，图片由 `mock/images.ts` 按 `/image` 的约定在前端程序化生成，不发请求：序号逢 10 的图为 7680×4320，其余为 3840×2160，像素按固定公式生成，第 0 层瓦片逐像素精确，并模拟 20–120 ms 的生成耗时。示例数据没有文件大小，放大时总走瓦片。

#### 测试

- `npm test` 用 `node --test` 直接运行 `src/**/*.test.ts`（靠 Node 自带的类型擦除，不需要额外依赖），覆盖几何计算、请求调度、LRU、虚拟滚动、Alt 匹配、预取、换图规则、列表索引、URL 规范和示例图片。为此 `pages/compare/` 下的模块互相导入时带 `.ts` 后缀，类型用 `import type` 导入，不用 enum、namespace 和构造函数的参数属性；`tsconfig.json` 相应打开了 `allowImportingTsExtensions`，并排除 `*.test.ts`。
- 地址带 `?perf=1` 时，`window.__cmpPerf` 给出各类请求的并发峰值、开始和中止次数、位图占用字节数和组件渲染次数，并打 `cmp:switch`、`cmp:paint:<结果集 ID>:<层级>` 的 performance mark。
- `npm run e2e`（`e2e/compare-mock.mjs`）：示例数据模式下逐项操作对比页的全部交互，检查页面无报错并截图。需要先在另一个终端运行 `npx vite --port 5180`。
- `npm run e2e:perf`（`e2e/compare-perf.mjs`）：对真实的中心服务和 Agent 跑下面的性能场景并按门槛判定，结果写到 `$OUT_DIR/perf-<标签>.json`。
- 两个 e2e 脚本使用全局安装的 playwright，浏览器取自 `PLAYWRIGHT_BROWSERS_PATH`（默认 `/opt/pw-browsers`），不在项目里安装依赖。

性能测试的流程：

```sh
python scripts/make_compare_dataset.py --out /data/cmp   # 6 组 × 2 万张；--small 为 3 组 × 2000 张
python scripts/bench_stack.py --data /data/cmp --build   # 本机启动 Agent 和中心服务并登记结果集；--no-pillow 测中心服务生成
cd web && npm run e2e:perf -- --data /data/cmp [--only S1,S2] [--runs 3]
python scripts/bench_images.py --data /data/cmp          # 后端接口基准，自己启动有 / 无 Pillow 两套环境，不要与 bench_stack.py 同时运行
```

S8 另需数据目录下有名为 `k8-0` 到 `k8-5` 的 8K 结果集。

#### 性能实测

环境：

- 数据集由 `make_compare_dataset.py` 生成，共 6.2 GB：6 组 × 2 万个文件名，每组硬链接到 20 张不同的 3840×2160 PNG（每张约 17 MB），另有 6 张 8K PNG（67 MB）和 2 张 TIFF，每组 5 个缺失文件，每 1000 张有一张已知图案；另有 6 组各 40 张 7680×4320（`k8-0` 到 `k8-5`）。
- 用 `bench_stack.py` 启动：Agent 装有 Pillow，默认 2 个解码线程；uvicorn 托管 `web/dist`。
- 4 核沙箱，浏览器、中心服务和 Agent 共用 CPU。
- 无头 Chromium，1920×1080，DPR 1，`?perf=1`，没有注明时各跑 3 次。
